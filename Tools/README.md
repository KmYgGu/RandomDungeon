# 검증 환경 (Unity 없이 돌리는 컴파일 + 테스트)

Unity 에디터를 켜지 않고 게임 코드를 컴파일하고, 순수 계산 부분을 실제로
돌려 보는 곳이다. **코드를 고쳤으면 여기부터 돌린다.**

## 돌리는 법

```bash
dotnet run --project Tools/Verify/Verify.csproj
```

이 한 줄이 게임 소스 컴파일(`Check`)까지 함께 한다. 마지막 줄이 `ALL PASS` 여야 한다.

컴파일 결과만 보고 싶으면:

```bash
dotnet build Tools/Check/Check.csproj --no-incremental
```

**에러 0 / 경고 0 이 기준선이다.** 경고가 하나라도 늘었으면 그건 내가 늘린 것이다.

## 무엇이 들어 있나

| | |
|---|---|
| `Check/Check.csproj` | `Assets/Code/**` 와 `Assets/RCode/**` 의 `.cs` 를 전부 컴파일한다. 게임을 빌드하는 게 아니라 문법·형 오류만 잡는다. |
| `Verify/Verify.csproj` | 위에서 나온 `Check.dll` 을 참조해 실제 클래스를 직접 호출한다. |
| `Verify/Program.cs` | 테스트 본문. |
| `Common.props` | 두 프로젝트가 함께 쓰는 경로 설정. |

## 지금 있는 테스트 10종

던전 생성 쪽은 무작위라 한 번 돌려서는 알 수 없으므로 수천 번씩 돌린다.

- **문 배치** 5,000 케이스 — 문이 늘 벽 위에 있고 방 안팎에 맞닿는가
- **통로 경로** 10,000 케이스 — 경로가 끊기거나 대각선으로 튀지 않는가
- **방 연결 그래프** 2,000 케이스 — 모든 방이 하나로 이어지는가
- **달리기 상태** — 걸음 수, 방향 고정, 정지 사유 기록
- **방향키 잠금** — 잠금 중 입력이 새지 않는가
- **대각선 유예** — 대각선 의도가 직선 한 칸으로 새지 않는가
- **버튼 판정** — 짧게 누름, 소비, A+B 동시 입력
- **입력 소유권** — `InputFocus` 이동 규칙
- **추격 길찾기** — 우회 지형에서 실제로 도달하는가
- **원거리 판정** — 대각선 틈으로 날아가는 규칙
- **새 판 초기화** — 지난 판의 수치·가방·장비·입력 권한이 넘어오지 않는가

마지막 것은 특히 **에디터에서는 절대 드러나지 않는** 종류다. 판 단위 상태를
`static` 으로 들고 있는데, 에디터는 Play 를 누를 때마다 도메인을 다시 로드해
저절로 초기화해 주기 때문이다. 빌드에서는 그런 일이 없다. 그래서 에디터가 아닌
이곳에서 확인한다.

## 여기서 확인할 수 없는 것

Unity 런타임이 있어야 하는 것은 손대지 않는다.

- MonoBehaviour 의 생명주기(`Awake`/`Start`/`Update`)
- 코루틴, `WaitForSeconds`
- 씬 로드, `Destroy`, `DontDestroyOnLoad`
- `Tilemap`, 프리팹, Inspector 연결

즉 **`ALL PASS` 는 "에디터에서 잘 돈다" 는 뜻이 아니다.** 반대로 여기서
실패하면 확실히 잘못된 것이다. 실제 플레이 확인은 사람이 해야 한다.

## 테스트를 새로 넣을 때

`Verify/Program.cs` 의 `Main()` 에 호출 한 줄을 더하고 메서드를 쓴다.
판정은 `Check(조건, "실패했을 때 보여 줄 말")` 하나뿐이다.

**넣은 테스트는 반드시 한 번 실패시켜 봐야 한다.** 고친 코드를 잠깐 되돌리거나
기대값을 일부러 틀리게 해서 `FAILURES` 가 뜨는 걸 확인한 다음 되돌린다.
이걸 안 하면 아무것도 검사하지 않는 테스트가 조용히 통과만 하고 있게 된다.
상태를 더럽혀 놓고 시작하는 테스트라면, 더럽히기가 실제로 먹혔는지도
함께 검사해 둔다(`준비 실패: ...` 로 시작하는 줄들이 그것이다).

## 환경

- **.NET SDK** 가 필요하다(`dotnet --version`).
- **Unity 2020.3.21f1** 설치 경로를 참조한다. 버전이나 위치가 다르면
  `Common.props` 의 `UnityVersion` 을 바꾸거나 명령줄에서 덮어쓴다:

  ```bash
  dotnet run --project Tools/Verify/Verify.csproj -p:UnityManaged="D:/Unity/2021.3.0f1/Editor/Data/Managed/UnityEngine"
  ```

- TextMeshPro 와 uGUI 는 `Library/ScriptAssemblies/` 에서 가져온다.
  `Library/` 는 git 에 올라가지 않으므로, **저장소를 새로 받았다면 Unity 로
  프로젝트를 한 번 열어야** 이 폴더가 생기고 빌드가 된다.

## 왜 `Assets/` 밖에 있나

Unity 는 `Assets/` 아래의 모든 `.cs` 를 게임 코드로 컴파일하려 든다.
여기 있는 `Program.cs` 는 `Main()` 을 가진 콘솔 프로그램이라 그 안에 두면
게임 빌드가 깨진다. 그래서 프로젝트 루트의 `Tools/` 에 있다.

`.gitignore` 에도 손을 대 두었다. Unity 용 `.gitignore` 는 `*.csproj` 를 통째로
무시하는데(에디터가 자동 생성하는 것들 때문이다), 그러면 여기 것도 함께 사라진다.
`!Tools/**/*.csproj` 로 되살려 두었으니 **그 줄을 지우지 말 것.**
